# SillyTavern扩展开发：浮动按钮与弹窗页面实战指南

## 引言
本教程旨在提供一个在SillyTavern扩展中，创建功能完备、布局稳定、移动端友好的浮动按钮和弹窗页面的详细指南。我们将以 `AutoCardUpdaterExtension` 项目的实战经验为基础，解析其最终采用的、经过多次迭代验证成功的核心技术方案。

本教程涵盖了从HTML注入、CSS精确定位、移动端适配到JavaScript交互逻辑的完整流程，特别是解决了在SillyTavern这种复杂宿主环境中常见的布局和兼容性问题。

---

## 第一步：通过JavaScript动态创建HTML元素

为了保持扩展的独立性，避免直接修改SillyTavern的核心文件，最佳实践是在扩展的 `index.js` 中通过JavaScript动态创建并注入所有UI元素。

### 1.1 创建浮动按钮
在 `initializeCharCardViewer_ACU` 函数中，我们首先检查按钮是否已存在，然后创建并添加到 `<body>` 中。

```javascript
// index.js -> initializeCharCardViewer_ACU()

// 检查按钮是否已存在，避免重复创建
if (jQuery_API_ACU(`#${CHAR_CARD_VIEWER_BUTTON_ID}`).length > 0) {
    return;
}

// 定义按钮的HTML结构，包含ID、title和FontAwesome图标
const buttonHtml = `<div id="${CHAR_CARD_VIEWER_BUTTON_ID}" title="查看角色卡" class="fa-solid fa-address-card"></div>`;

// 使用jQuery将按钮HTML字符串附加到文档的body中
jQuery_API_ACU('body').append(buttonHtml);

// 后续逻辑...
```

### 1.2 创建弹窗页面
弹窗页面的HTML结构相对复杂，因此我们专门用一个函数 `createCharCardViewerPopupHtml_ACU` 来生成它。这个函数会根据传入的数据（例如角色列表）动态构建HTML，然后在需要时（如点击按钮时）再注入到 `<body>` 中。

```javascript
// index.js -> showCharCardViewerPopup_ACU()

// 1. 调用函数生成完整的弹窗HTML字符串
const popupHtml = createCharCardViewerPopupHtml_ACU(characters);

// 2. 将生成的HTML注入到body中
jQuery_API_ACU('body').append(popupHtml);

// 3. 获取刚创建的弹窗元素的jQuery对象，以备后续操作
const $popup = jQuery_API_ACU(`#${CHAR_CARD_VIEWER_POPUP_ID}`);

// 4. 为弹窗内部的元素（如关闭按钮、保存按钮）绑定事件
bindCharCardViewerPopupEvents_ACU($popup);
```
**核心思想**：UI元素的生命周期由JS完全掌控，需要时创建，关闭时销毁 (`closeCharCardViewerPopup_ACU` 函数会调用 `.remove()`)，从而实现干净、无冲突的集成。

## 第二步：稳健的CSS布局与样式 (含移动端适配)

这是确保UI在SillyTavern复杂环境中正确显示的关键。经过多次迭代，我们最终确定了以下最可靠的CSS方案。

### 2.1 浮动按钮的样式
```css
/* style.css */
#autoCardUpdater-viewer-button {
    position: fixed !important; /* !important确保不会被覆盖。fixed使其相对于浏览器窗口定位 */
    z-index: 1050;              /* 一个足够高的z-index，确保按钮在绝大多数UI元素之上 */
    cursor: grab;               /* 初始状态为可抓取手势 */
    width: 48px; 
    height: 48px;
    
    /* 主题自适应样式 */
    background-color: var(--primary-color, #007bff); /* 使用酒馆变量，提供备用值。这也是一个重要的备用色，以防背景图片加载失败。 */
    color: var(--primary-text-color, white);
    border-radius: 50%;
    box-shadow: 0 4px 8px rgba(0,0,0,0.2);
    display: flex;
    align-items: center;
    justify-content: center;
}
```
**解析**: `position: fixed` 是浮动按钮的核心。它使得按钮脱离文档流，其位置是相对于浏览器视口（viewport）来计算的。**使用 `var(...)` CSS变量**可以让你的UI自动适应SillyTavern的主题切换，这是非常重要的最佳实践。

### 2.2 弹窗页面的最终布局方案
```css
/* style.css */
.char-card-viewer-popup {
    /* 强制应用定位和尺寸，防止被SillyTavern的全局样式污染 */
    position: fixed !important;

    /* 核心定位方案：放弃所有垂直居中技巧，采用简单的顶部对齐 */
    top: 5vh !important;               /* 距离屏幕顶部5%的视口高度，为SillyTavern顶栏留出安全距离 */
    
    /* 核心水平居中方案：只在水平方向居中，避免垂直transform带来的问题 */
    left: 50% !important;
    transform: translateX(-50%) !important; 

    width: 95vw !important;             /* 在移动端，宽度占屏幕的95% */
    max-width: 800px !important;        /* 在大屏幕上，最大宽度不超过800px */
    
    /* 移动端适配关键：限制最大高度，防止弹窗超出屏幕 */
    max-height: 80vh !important;        /* 弹窗最大高度为屏幕的80%，确保底部有足够空间，关闭按钮永远可见 */

    /* Flexbox布局，用于内部元素(header, body, footer)的垂直排列 */
    display: flex;
    flex-direction: column;
    overflow: hidden; /* 隐藏弹窗自身级别的溢出，强制由内部body滚动 */

    /* 主题自适应样式 */
    background-color: var(--background-color, #fff);
    color: var(--text-color, #000);
    border: 1px solid var(--border-color, #ddd);
    border-radius: 8px;
}
```
**为什么这个方案有效？**
经过多次失败后我们发现，SillyTavern的某些容器可能影响了 `transform: translateY(-50%)` 的计算，导致垂直居中失败。最终方案彻底放弃了垂直居中，改为简单的、可预测的顶部对齐。**`max-height: 80vh` 是移动端适配的生命线**，它确保了即使在小屏幕上，弹窗也不会过高而导致底部内容（如关闭按钮）被裁切。

**⚠️ 实战踩坑：主题兼容性与输入框**
- **问题**: 即使弹窗布局稳定，内部的 `<input>`, `<textarea>`, `<select>` 等表单元素也极易受到SillyTavern主题的影响，出现文字颜色和背景色相同导致看不清的问题。
- **解决方案**:
    1.  **ID选择器优先**: 给弹窗最外层容器一个唯一的ID，例如 `id="my-popup-container"`。
    2.  **强制覆盖**: 在CSS中，使用ID选择器来为这些表单元素定义一套独立的、高对比度的样式，并使用 `!important` 来确保最高优先级。
    ```css
    #my-popup-container input,
    #my-popup-container textarea,
    #my-popup-container select {
        background-color: #2B2D31 !important;
        color: #F2F3F5 !important;
        border: 1px solid #4E5058 !important;
    }
    ```
    这虽然牺牲了部分主题的自适应性，但保证了插件在任何情况下都**可用**，这是最重要的。

### 2.3 弹窗内部的滚动区域
```css
/* style.css */
.char-card-viewer-popup-body {
    flex-grow: 1;         /* 关键！此元素将自动填充父容器(弹窗)中所有剩余的垂直空间 */
    overflow-y: auto;     /* 当内容超出其高度时，允许垂直滚动 */
    padding: 20px;

    /* 根据用户要求隐藏滚动条 */
    scrollbar-width: none; /* Firefox */
    -ms-overflow-style: none;  /* IE and Edge */
}
.char-card-viewer-popup-body::-webkit-scrollbar {
    display: none; /* Chrome, Safari, and Opera */
}
```
**解析**: 这是实现弹窗内容滚动的核心。在`.char-card-viewer-popup`设置为 `display: flex; flex-direction: column;` 后，其子元素 `header` 和 `tabs` 都是固定高度的，只有 `body` 设置了 `flex-grow: 1`。这意味着 `body` 会像海绵一样，自动撑满父容器中除了 `header` 和 `tabs` 之外的所有可用空间。因为父容器有 `max-height` 限制，所以 `body` 的高度也是受限的。此时，`overflow-y: auto` 就能在内容超出时完美工作。

## 第三步：强大的JavaScript交互逻辑 (含移动端拖动)

### 3.1 按钮拖动与位置记忆 (区分点击与拖动)
这是确保浮动按钮交互体验的关键。一个常见的陷阱是，简单的拖动逻辑会阻止“单击”事件的触发。以下是经过实战检验的、能够精确区分用户“单击”和“拖动”意图的最终方案。

```javascript
// index.js -> makeButtonDraggable()
function makeButtonDraggable(button) {
    let isDragging = false;
    let hasMoved = false; // 关键状态：用于判断是否发生了实质性移动
    let offset = { x: 0, y: 0 };

    // 统一的拖动开始事件 (兼容鼠标和触摸)
    const dragStart = (e) => {
        isDragging = true;
        hasMoved = false; // 每次开始拖动时，重置移动状态
        button.css('cursor', 'grabbing');
        const event = e.type === 'touchstart' ? e.originalEvent.touches[0] : e;
        const buttonPos = button.offset();
        offset.x = event.pageX - buttonPos.left;
        offset.y = event.pageY - buttonPos.top;
        e.preventDefault(); // 防止触摸时滚动页面
    };

    // 统一的拖动过程事件
    const dragMove = (e) => {
        if (!isDragging) return;
        hasMoved = true; // 只要触发了move事件，就标记为已移动
        const event = e.type === 'touchmove' ? e.originalEvent.touches[0] : e;
        button.css({
            top: event.pageY - offset.y + 'px',
            left: event.pageX - offset.x + 'px',
            right: 'auto', // 拖动时清除right/bottom属性，以left/top为准
            bottom: 'auto'
        });
    };

    // 统一的拖动结束事件
    const dragEnd = () => {
        if (!isDragging) return;
        isDragging = false;
        button.css('cursor', 'grab');
        // 只有在实际移动后才保存位置，避免单击也触发保存
        if (hasMoved) {
            localStorage.setItem(
                'your-storage-key-for-button-pos', // 替换成你自己的localStorage键
                JSON.stringify({ top: button.css('top'), left: button.css('left') })
            );
        }
    };

    // 绑定事件
    button.on('mousedown.draggable touchstart.draggable', dragStart);
    $(document).on('mousemove.draggable touchmove.draggable', dragMove);
    $(document).on('mouseup.draggable touchend.draggable', dragEnd);

    // 单独处理点击事件
    button.on('click', (e) => {
        // 只有在没有发生移动时，才执行点击操作
        if (hasMoved) {
            e.stopPropagation(); // 阻止事件冒泡，以防万一
            return;
        }
        // 在这里执行你的弹窗逻辑，例如 showPopup();
        console.log('Button was clicked!');
    });

    // 关键的移动端修复：为所有交互元素绑定 touchend
    // 在SillyTavern中，仅有 `click` 事件在移动端可能响应迟钝或被阻止。
    // 必须为所有按钮、链接等同时绑定 `touchend` 事件。
    // 一个好的实践是在事件处理函数中调用 e.preventDefault() 来避免“双击”问题。
    
    // 示例：
    $('#my-popup .close-button').on('click touchend', function(e) {
        e.preventDefault();
        e.stopPropagation();
        closePopup();
    });
}

// 在按钮初始化时，读取并应用保存的位置
// index.js -> initializeCharCardViewer_ACU()
const savedPosition = JSON.parse(localStorage.getItem(STORAGE_KEY_VIEWER_BUTTON_POS_ACU) || 'null');
if (savedPosition) {
  $viewerButton.css({ top: savedPosition.top, left: savedPosition.left });
} else {
  // 如果没有保存的位置，则设置一个默认初始位置
  $viewerButton.css({ top: '120px', right: '10px', left: 'auto' });
}
```
**解析**:
- **`hasMoved` 状态**: 这是整个逻辑的核心。它在拖动开始时被重置为 `false`，在拖动过程中被设置为 `true`。
- **分离的 `click` 事件**: 我们不再试图在 `dragEnd` 中判断是否是点击。而是单独绑定一个标准的 `click` 事件。
- **点击逻辑**: 在 `click` 事件处理器中，我们检查 `hasMoved` 标志。如果它为 `true`，意味着用户刚刚完成了一次拖动，我们就不执行任何操作。如果它为 `false`，则意味着这是一次纯粹的单击，此时我们就可以安全地执行弹出窗口等操作。

这个方案彻底解决了“拖动后触发点击”和“无法点击”的经典问题，提供了最符合直觉的用户体验。

### 3.2 解决窗口大小调整导致按钮消失的BUG
```javascript
// index.js -> initializeCharCardViewer_ACU()

// 添加窗口大小调整事件监听器
let resizeTimeout_ACU;
jQuery_API_ACU(window).on('resize.charCardViewer', function () {
    // 使用setTimeout进行去抖动，避免频繁触发，提高性能
    clearTimeout(resizeTimeout_ACU);
    resizeTimeout_ACU = setTimeout(function () {
        const button = jQuery_API_ACU(`#${CHAR_CARD_VIEWER_BUTTON_ID}`);
        if (!button.length) return;

        // 获取按钮当前位置和窗口尺寸
        let currentLeft = button.offset().left;
        let currentTop = button.offset().top;
        const maxLeft = jQuery_API_ACU(window).width() - button.outerWidth();
        const maxTop = jQuery_API_ACU(window).height() - button.outerHeight();

        // 检查并修正位置，确保按钮不会超出窗口边界
        if (currentLeft > maxLeft) currentLeft = maxLeft;
        if (currentLeft < 0) currentLeft = 0;
        if (currentTop > maxTop) currentTop = maxTop;
        if (currentTop < 0) currentTop = 0;

        // 应用修正后的位置并重新保存
        button.css({ top: currentTop + 'px', left: currentLeft + 'px' });
        localStorage.setItem(
            STORAGE_KEY_VIEWER_BUTTON_POS_ACU,
            JSON.stringify({ top: button.css('top'), left: button.css('left') })
        );
    }, 150);
});
```
**解析**: 这是确保UI健壮性的关键一步。当浏览器窗口大小改变时，此事件监听器会重新检查按钮的位置。如果它因为窗口缩小而跑到了屏幕外，代码会强制将其拉回边界内，并更新存储的位置。这彻底解决了按钮“消失”的问题。

## 第四部分：高级技巧与总结

### 4.1 简化交互：即时反馈代替二次确认
在 `AutoCardUpdaterExtension` 的实践中发现，对于“删除”这类操作，频繁的二次确认弹窗会打断用户心流。一种更现代的设计是：
- **移除确认弹窗**: 点击删除按钮后，不弹出“你确定吗？”。
- **提供即时UI反馈**: 对应的UI元素（如一个卡片）立即从界面上消失。
- **提供撤销选项**: （可选，但体验更佳）在底部或顶部显示一个短暂的 `toastr` 通知，例如“条目已删除。[撤销]”，允许用户在几秒内取消操作。

这种“乐观UI”的设计让操作更流畅，但需要开发者对操作的可恢复性有信心。

### 总结
创建一个稳定、可靠、体验优秀的浮动UI系统，关键在于：
1.  **动态注入**: 保持扩展的独立性。
2.  **稳健的CSS**: 放弃在复杂环境中不稳定的布局技巧，回归最简单、最可预测的CSS规则，并**优先考虑移动端适配**（如 `max-height`）。
3.  **主题自适应**: 广泛使用CSS变量，确保UI与SillyTavern融为一体。
4.  **Flexbox布局**: 利用 `flex-grow` 和 `overflow` 精确控制内部元素的尺寸和滚动行为。
5.  **健壮的JS**: 编写**兼容多端**的事件处理器，处理好边界情况（如窗口大小调整），并利用 `localStorage` 持久化用户的偏好设置。
6.  **优化交互**: 思考如何简化流程，用更优雅的方式提供反馈。
